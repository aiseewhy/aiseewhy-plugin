# Fix a blocked AI crawler

## Goal

Turn a finding into a verified fix: the crawler that was blocked gets the page, and a second audit shows it.

## Tools (AISeeWhy MCP)

- `audit_url(url, language)`: before and after. The report's fixes are ready to paste.
- `explain_finding(finding_id)`: the cause and the fix for one finding id.

## Workflow

1. **Get the evidence.** If there is no fresh audit of the page, run `audit_url`. Write down for each blocked crawler: the finding id, the HTTP status, the firewall or CDN the report names, and the robots.txt line if any.
2. **Find where the block lives.** It is usually one of:
   - **Firewall or bot protection** (`access.blocked`, `access.all_blocked`, 403/429/503 or a challenge page): Cloudflare (Bot Fight Mode, "Block AI bots", WAF custom rules), AWS WAF, Akamai, Vercel or Netlify firewall, Sucuri, Wordfence or a hosting panel. The fix is in that dashboard, not in the code.
   - **robots.txt** (`robots.disallowed`, `robots.access_conflict`): a file in the repository (often `public/robots.txt`, `static/robots.txt`) or generated by the framework or CMS (Next.js `app/robots.ts`, WordPress SEO plugins, Shopify `robots.txt.liquid`).
   - **JavaScript-only content** (`content.js_only`, `access.soft_block` with tiny text): the page renders its text in the browser. The fix is server-side rendering, static generation or prerendering for that route.
   - **Redirects** (`access.redirect_diff`): a rule that sends crawlers somewhere else (geo or bot redirects, a login wall).
3. **Ask before changing policy.** Allowing a training crawler (GPTBot, ClaudeBot, Google-Extended, CCBot …) is a business decision. Search and user crawlers are what AI answers need; confirm with the user before you open training crawlers.
4. **Apply the fix.**
   - In the code (robots.txt, framework robots config, rendering): make the smallest change, show the diff, run the project's build or tests.
   - In a dashboard: you cannot click it for the user. Give the exact steps and the rule text from the report (for Cloudflare the report gives a skip rule expression for verified AI crawlers), and wait until the user says it is done.
   - Never weaken protection for everyone to let one crawler in. Prefer rules that match verified bots or the specific user agents.
5. **Prove it.** After the change is deployed, run `audit_url` again on the same URL. Compare the access rows crawler by crawler and the score. Caches matter: if nothing changed, check that the deploy finished and the CDN cache was purged, then audit again.

## Report to the user

- Before and after for each crawler that was blocked (status, verdict), and the score before and after.
- What was changed and where (file and line, or dashboard and rule).
- Anything still blocked and why (for example a training crawler kept blocked on purpose).

The audit runs from AISeeWhy's servers. A firewall that checks the crawler's published IP ranges may still treat the real crawler differently; the user's server logs are the final word.
